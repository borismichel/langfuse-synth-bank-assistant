# Voice

Enable **Voice** in Configuration before deployment. It defaults to off. Depot resolves OpenAI only when this option is enabled; the banking chat provider remains independently selected. Speech uses the explicit `speech_to_text` (`gpt-transcribe`) and `text_to_speech` (`gpt-realtime-2.1-mini`) roles. The latter uses the Realtime WebSocket API to read the completed banking answer, with tools disabled and its spoken transcript checked against that answer. There is no fallback to the deprecated Speech API.

Voice availability reports configured roles without a paid model probe. Model access, real-provider output and deployed media playback still need release qualification. Every actual transcription, banking model call and speech response requires a fresh Depot operation check. A denial or unavailable check stops that dispatch; provider SDK retries are disabled. Depot's cap is an estimate based on active container hours, not exact provider billing. Speech usage is recorded separately from banking generation usage; missing usage or cost is unknown, never zero.

## Participant walkthrough

1. Select the synthetic customer in **Customer assistant**. Voice uses that same conversation, customer, guardrails and banking state; its customer field is read-only.
2. Open **Voice**, select English or Spanish, then **Record** and **Stop recording**, or choose an existing recording. Microphone capture requires a supported browser on HTTPS (loopback development is supported). Unsupported browsers can upload instead. WAV, MP3, WebM and MP4 files are limited to 10 MiB; microphone recording stops at 60 seconds. The server counts actual multipart bytes, including requests without a trustworthy Content-Length.
3. Press **Send audio**. The returned transcript and banking answer join the text conversation. Play the reply with its audio control. The voice is AI-generated; use only synthetic recordings. Bundled examples retain upstream provenance and are filtered to the selected customer; they are never generated during deployment.
4. A banking mutation must still display **Confirm action**. Audio requesting an action does not grant confirmation. Confirming uses the same protected action and idempotent receipt as text. Feedback attaches to the nested assistant answer, not the outer voice observation or transcription.
5. Open the exact Langfuse trace. It contains the voice parent, the nested banking assistant and its retrieval/MCP tree, plus distinct transcription and speech generations. Policy judges target the nested assistant. Local playback and target media delivery have separate states: **uploaded** confirms exact target media records, not native playback or downloaded-byte verification. Check native playback explicitly during release qualification.

## Recovery and lifecycle

- **Cancel** stops pending work. Once banking has completed, cancellation retains its answer and confirmation receipt even if speech is cancelled. It cannot undo completed actions or provider charges.
- A network interruption offers **Retry same request**. It reuses the original audio, language, conversation and request identity; changed input under an existing identity is rejected. Media status polling never repeats STT, banking or speech. If speech failed after banking, use the saved text answer; there is no automatic paid speech retry.
- A media upload outage leaves local playback available while the SDK attempts delivery. Do not resubmit the banking request to repair target media. Upload status remains pending until the exact observation's input/output references and public media records agree. No client-supplied media identifiers or presigned URLs are accepted.
- Two voice requests may run simultaneously per instance. Storage is reserved before any paid dispatch, with a 64 MiB budget for input plus worst-case reply reservations and at most 128 requests across participants. A capacity rejection requires resetting the participant's demo state and waiting for pending SDK media delivery to drain. Reset and new conversations remove local audio immediately, but cannot free the upload budget while SDK workers still retain those bytes. Spoken output is bounded to 60 seconds of 24 kHz mono PCM.
- **New conversation** clears that participant's local audio while retaining banking changes. **Reset demo state** cancels pending work, clears owned audio and restores the selected synthetic customer. Langfuse history remains. Replacing/stopping the instance discards all local audio. Audio GET/range requests require the owning HttpOnly session cookie; opaque URLs are not authority.
- The browser releases microphone tracks on stop, reset or navigation. Application shutdown gives outstanding SDK delivery and shutdown separate two-second waits; unconfirmed delivery remains pending. MCP/n8n/Jaeger children never receive speech keys or the operation-check capability. APM exports operation metadata only, excluding transcript, audio and credentials.

## Model-free regression

The locked development environment runs `tests/test_voice.py` against real OpenAI HTTP/WebSocket clients, LangGraph and Langfuse SDK5 with local external API fixtures. It covers actual byte limits, async replay/cancel, owned range playback, reset, configured readiness, provider denials and bounded shutdown. Existing banking/native-provider tests retain their assertions with the public operation-permit fixture.

For the browser rehearsal, install Chromium with `.venv/bin/python -m playwright install chromium`, then run `VOICE_BROWSER=1 PYTHONPATH=src:demos/bank-assistant .venv/bin/python tests/sdk_voice_case.py`. Hosted CI runs this with a synthetic Chromium microphone. It records English, uploads the bundled Spanish recording, gives exact-answer feedback, explicitly confirms an action and resets through `/live/voice-fixture/`. This is a model-free protocol and UI test, not speech-recognition accuracy or real-target qualification.

Release qualification must repeat both languages and input modes with the actual OpenAI account, selected chat provider, authenticated deployed prefix and target/presigned storage egress. Retrieve and play the owned audio, inspect native media playback, read back exact trace/assistant subjects and policy binding, verify usage once per provider call, then reset and stop. Retain explicit evidence for unavailable models or blocked storage hosts. Required voice qualification is pending until that evidence exists.
